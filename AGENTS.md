# Patternly repository instructions

Personal workflow, review proportionality and model selection follow the global working agreements. Keep this file focused on Patternly contracts.

- Przy pierwszym zastosowaniu skilla podaj użytkownikowi w aktualizacji nazwę skilla i konkretny cel jego użycia.
- Use `docs/PATTERNLY-WORKING-PLAN.md` as the canonical working plan; the root plan file is a link, not another plan. Keep `.agent/WORKING_STATE.md` as one concise current handoff with evidence links, unresolved gaps and next action. Do not duplicate the plan or prepend competing checkpoint summaries. Resolve historical claims against current source and applicable runtime evidence.
- Distinguish evidence for one behavior, full local acceptance of the requested scope, and deployment/release readiness. A pushed work-in-progress checkpoint does not establish acceptance or deployment. Identify the source of any new blocking requirement and the risk it addresses.
- For preservation checks, classify storage entries by canonical learning progress, user settings, account/session state, lifecycle markers, cache and downloaded content. Compare each category against the operation's allowed changes. Whole-store inequality alone does not prove lost learning progress, and equal known entries do not explain unknown records. Trace unknown entries to their producer/consumer and assess whether their changes can affect required preserved data. Until that is established, limit the preservation claim to verified categories; recording uncertainty alone does not satisfy a material preservation criterion.
- For recovery evidence, record where interruption occurred relative to local persistence, server effects, SDK/account transition and ACK. A restart after ACK proves post-completion persistence, not resumption of an interrupted operation. Select interruption points from the required recovery contract and concrete regression risks.
- For PROFILE simulator acceptance, the owner has authorized clearing Patternly app data on the existing iPhone 17 now and in future runs when needed for an isolated test. Do not ask again for that exact cleanup. This does not authorize deleting repository files, production data, external user accounts, emulator backend data outside the task fixture, or creating/reinstalling a duplicate app/device without a concrete need. A task-specific restriction can narrow this authorization.
