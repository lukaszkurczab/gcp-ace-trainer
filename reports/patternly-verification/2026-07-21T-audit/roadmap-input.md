# Roadmap input

## A. Stop-the-line

- **P1 DF-001 / CM-002:** a product that documents Cloud Certification as a family has no real content ingress or bundled runtime artifact. It cannot be represented as a working vertical slice.

## B. Vertical-slice gaps

- Algorithms proves content → immediate feedback → leave/relaunch/resume for one item. Summary, Progress mutation, due/review and fixed-40 completion remain unobserved.

## C. Content–runtime mismatch

- No Algorithms byte/version mismatch found.
- Cloud is absent across source ingress and runtime bundle.
- Item-level UI/artifact equality is unprovable without a correlation key.

## D–F. UX, readiness, QA

- Composite active-session accessibility label makes reliable test targeting fragile.
- Details expansion has no stable audit handle.
- Current test contract is stale against the observed Practice Hub option list.
- The current audit cannot reproduce or correlate a session item from logs alone.

## G. Owner decisions

- Decide whether Cloud Certification is in current product scope before investing in its vertical slice. Repo evidence cannot resolve product promise versus implementation absence.

## H. Candidate vertical work packets

1. **Algorithms completion evidence — M, high confidence.** Goal: run and capture one full 10-item session through Summary, review, Progress and relaunch. Depends on a clean/reproducible local state. Non-goal: changing scoring. Done when item IDs, screenshots and durable state join to the artifact.
2. **Certification canonical readiness — L, high confidence.** Goal: establish the actual manual source → approval → activation → artifact → runtime slice for one certification mode. Depends on owner scope decision. Non-goal: hiding the track or supplying fixture content.
3. **Runtime auditability — S, high confidence.** Goal: expose stable, assistive-technology-safe audit selectors/correlation without altering learner content. Depends on accessibility design review. Done when a real item can be joined to artifact ID and Details/resume can be targeted deterministically.
4. **Practice Hub contract reconciliation — S, high confidence.** Goal: make the canonical test expectation match the intended current options or remove unintended behavior. Depends on product decision about Default Practice. Done when tests and real Hub behavior agree.
5. **Simulation end-to-end evidence — M, medium confidence.** Goal: execute exact 40 unique simulated items and materialized Summary. Depends on deterministic reset and runtime auditability. Non-goal: changing the fixed-40 selection contract.
