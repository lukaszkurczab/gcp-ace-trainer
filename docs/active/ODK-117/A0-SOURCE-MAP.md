# ODK-117-A0 — mapa źródeł tekstu i wyjątków

**Stan zadania:** `DONE / niezależne QA PASS` — zmapowano wszystkie aktywne kanały oraz wieloklasowy, powtarzalny inventory scan; klasyfikacja i migracja dynamicznie składanej copy należą do A3.
**Stan zakresu ODK-117:** `PARTIAL` — aplikacja nadal udostępnia tylko `en` i `pl`; A1–A5 i B pozostają otwarte.
**Podstawa:** aplikacja `73c0bb15` plus widoczny, niezapisany diff AUD-04-D; backend `77c4e4c`, content `21707b6`, web `10e3182`.

## Wniosek

Teksty interfejsu nie mają jeszcze jednego źródła. Zwykłe UI używa i18next z zasobami EN/PL, ale współistnieją z bezpośrednimi literałami, mapami copy w komponentach, własnymi formatterami/presenterami, błędami domenowymi i osobną ścieżką dokumentów prawnych. Edukacyjny tekst pytania pochodzi z kanonicznego repo content i jest celowo angielski. Powiadomienie systemowe może być zbudowane z locale copy albo z angielskiego domyślnego tekstu aplikacyjnego.

Statusy poniżej opisują stan kodu: `DONE`, `PARTIAL`, `MISSING`, `RISK`. Poziom dowodu: `VERIFIED` — potwierdzone aktualnym kodem/konfiguracją/testem wskazanym w kolumnie; `INFERRED` — wynika z połączenia kodu, ale brak dedykowanego dowodu runtime; `UNVERIFIED` — wymaga dalszego sprawdzenia; `BLOCKED` — wymaga zależności spoza tego kroku. To mapa pochodzenia, nie ocena jakości przekładów ani pełny odbiór widoków.

## Luki w kolejności zależności

1. **A1 — runtime locale:** jeden kontrakt wspieranych języków, wybór ustawienia/system locale i zachowanie bez cichego fallbacku. Źródło: `AppPreferencesProvider`, `i18n.ts`, settings storage. Zależność dla wszystkich dalszych odbiorów.
2. **A2 — pięć pakietów namespace:** pełne `de/fr/es/it/et`, niezależny przegląd językowy i pełny parytet namespace. Nie generować niezweryfikowanych tłumaczeń.
3. **A3 — zwykłe UI:** przenieść pozostałe literały i lokalne słowniki do przyjętego kanału; dodać guard, by nowe widoczne copy nie omijało locale. Obejmuje walidacje, błędy, accessibility oraz alerty.
4. **A4 — prezentacje i formatowanie:** pozostałe formatter-y dynamiczne, plurale, kody → lokalna copy, metadane katalogu/tracków oraz granica locale w danych backendowych. Rozróżnić display od wartości protokołu/storage.
5. **A5 — odbiór:** testy i Maestro na istniejącym iPhonie 17 dla 7 języków, dużego tekstu, reprezentatywnych ekranów, błędów i alertów; obejrzeć prywatne screenshoty. Dowód VoiceOver device-only odsyłać do ODK-088.
6. **B-CONTRACT — po ODK-116-A:** wersje siedmiu locale prawnych szablonów i zmiennych na jawnym syntetycznym fixture; bez danych PO.
7. **B-VALUES — po ODK-116-B:** sprawdzić rzeczywiste wartości w dokumentach i interpolacji wszystkich locale przed FREEZE. Prawdziwe wartości nie blokują A1–A5 ani B-CONTRACT.

## Appendix — powtarzalny, kandydatowy inwentarz

Wszystkie poniższe polecenia uruchomiono z katalogu aplikacji. Testy zostały wykluczone, ponieważ są dowodem/fixture, a nie produkcyjnym źródłem tekstu. Wyniki są kandydatami statycznego wyszukiwania: dynamiczne wyrażenia mogą nie być znalezione, a dopasowanie nazwy nie dowodzi, że plik renderuje copy. Dla każdego broad scan jawnie podaję klasy fałszywych trafień. Nawiasy klamrowe rozwijają listę nazw plików. Skrót .ts[x] oznacza, że dla każdego wymienionego stem wynikiem jest konkretny plik .ts albo .tsx; nie oznacza obu rozszerzeń. Dokładny, potwierdzony przykład mieszanej pary backendowej to ContentPreparationGate.tsx oraz premiumNodeOfferPresentation.ts. A3 ma dodać guard nowych widocznych string expressions i ręcznie sprawdzić dynamicznie składane copy z poniższych widoków/helperów.
