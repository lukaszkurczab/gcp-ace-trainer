It is hidden when the model is unavailable/not ready, there is no action callback, or an existing primary/secondary action already opens the editor. The button emits the existing `adjust_schedule` action. `HomeScreen.handleHomePlanAction` routes that action through `learningPlanEditorCoordinator.startExistingEdit(selectedTrackId)` and navigates only for a ready result; no second reader or mutation path was added.
- The cold-bootstrap log records app launch on the existing iPhone 17 with retained data and no install or data clear. The first read attempt failed its Progress-root assertion because the development warning overlay remained visible (`COLD-READ.log`, screenshot 03). The successful retry explicitly dismissed the visible warning, then opened Progress and the existing editor (`COLD-READ-WARNING-DISMISSED.log`). This preserves the failed attempt and its cause instead of treating the retry as the first run.
- On the successful path, the device asserted Monday `09:15`, Wednesday `18:00`, and Saturday `18:00` in the editor, without changing inputs, saving, or creating a proposal (`COLD-READ-WARNING-DISMISSED.log`, `READ-SATURDAY.log`). I inspected screenshots 04–06: 04 shows the new entry beside the existing Continue action; 05 shows Monday `09:15` and Wednesday `18:00`; 06 shows all three saved times. I independently recomputed their SHA-256 values and they match `screenshot-manifest.json`.
- The post-refresh record binds the run to the current app bundle (HTTP 200, 69,484,684 bytes, SHA-256 `b6bed03c2da0c292b54280d27cdf11dd59bd3fa33ac589cb80183d5d467c38f4`), the existing iPhone 17 UUID, and the current smoke launcher. It records that the app was terminated before refresh and that neither installation nor data clearing occurred. The report records the existing backend and auth services unchanged.
- Source verification remains applicable: the independent actual-JSX focused run in `SOURCE-QA.md` passed 24/24; root's broader source run passed 41/41; typecheck and content/privacy boundary checks passed. The code-only harness does not substitute for the device evidence above.

This is a recorded, non-blocking test-environment interruption because the same retained-data cold process then completed the intended path and assertions. The saved screenshots and logs preserve both attempts.

Acceptance is limited to one current-smoke guest profile and the shown default UI configuration.
