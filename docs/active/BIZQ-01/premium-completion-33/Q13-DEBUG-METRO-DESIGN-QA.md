# Q13 Debug/Metro revision design QA

**Verdict: PASS WITH GAPS.** This is a credible way to verify the exact OOD23-to-OOD24 persisted-session/package contract under the existing smoke Auth Emulator path. The revision addresses a real source constraint: Release sets `__DEV__` false, so `readDevelopmentFirebaseAuthEmulatorOrigin()` intentionally refuses the smoke Auth Emulator origin. The account provider therefore cannot compose the existing smoke auth path in that Release runtime. Repeating Release or relaxing the guard would change the test boundary. Under Debug with `npm run start:smoke`, `__DEV__` is true, smoke mode is compiled, and the existing launcher verifies local Auth Emulator configuration and API `/ready` using GETs. This uses the already-supported local test path without provider or product changes.

The proposed behavior is equivalent to Q13's core content mismatch/resume contract: run the exact OOD23 JavaScript package, create one normal active unanswered session pinned to OOD23, cold-launch it under the same old source and verify exact resume, then switch only the Metro-served app source to exact OOD24, cold-launch the same Debug app/storage, and require the existing exact resolver to return the expected mismatch with item/order and zero-answer state preserved. The Metro sidecar must bind that receipt to the unchanged source-binding hash/nonce, current public content identity, verified Metro PID/CWD/port, and the existing app identity, while explicitly marking the evidence as Metro-served. It must never create synthetic app-tree/embedded-JS hashes or pass this evidence to the packaged-build comparator.
