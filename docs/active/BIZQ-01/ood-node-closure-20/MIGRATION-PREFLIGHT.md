# N04 package20 migration preflight

Status: bounded read-only implementation preflight. This records insertion points and preservation risks for a later exact design review; it does not approve a proof schema, an identity map, source changes, or admission.

## Existing path and insertion points

The current loader dispatches by the catalog's OOD `contentVersion` in `patternly-content/scripts/content/verify-migration.mjs:7061-7080`. The 19a branch validates the fixed 25-item Reason-only amendment, then the v19 branch validates its fixed 162 replacements. The migration-19a validator at `:6900-7058` reads the three actual N03 source files, checks their exact bytes and per-question hashes, restores the prior Reason strings, and calls the closed N03 proof with its private historical-source map. That private map is deliberately limited to the three N03 paths by `validateBizq01OodClosedCohortProof` at `:6689-6703`; it must remain so.

The least disruptive integration point, if the later identity review and exact design review support it, is a closed package20 version branch before the 19a branch in `loadBizq01OodSemanticProof`. That branch should validate the fixed N04 descriptor and reconstruct an in-memory 19a canonical snapshot, then pass that snapshot through the existing loader. This keeps the existing on-disk 19a checks, 25 Reason corrections, v19 proof, and immutable 17→16→13→12→11 history active. It must not pass N04 buffers as the 19a private map or broaden the existing private-context exception.

The current closed-cohort validator at `:6689-6860` is explicitly limited to the fixed v17/v19 descriptors. Its replacement loop requires each old ID to be absent from the current catalog (`:6801-6809`), which excludes same-ID corrections. The predecessor reconstruction itself filters current IDs before appending prior objects (`:6848-6867`), so a same-ID correction would not duplicate an ID there; the concrete incompatibility is the identity guard and the all-new-ID descriptor/result semantics. Preserve the accepted v17/v19 behavior. A package20-only closed branch may reuse this implementation only if its fixed descriptor/actions keep the existing cohorts unchanged and explicitly distinguish a content correction from an identity replacement; the exact implementation choice belongs to the later reviewed design.

## Identity-dependent reconstruction

Build the N04 predecessor source arrays from the frozen per-item identity decisions, not from a blanket `oldId → reservedNewId` rule:

- For a reviewed new-ID replacement, verify the current object under the exact new ID and its source membership; remove it from the predecessor and restore the hash-bound prior object under its old ID. Only these items belong in the semantic identity-replacement mapping returned to migration consumers.
- For a reviewed same-ID correction, verify the current and prior whole objects separately, including their equal ID and the exact changed fields. In the predecessor, remove the current object at that ID and restore the hash-bound prior object there. Carry this restoration into the internal global-history comparison while keeping it out of the semantic new-ID map; it must not masquerade as an `oldId → sameId` replacement.

Both paths still need exact fixed membership, unit/source/taxonomy, option identity and current-catalog/source equality checks. The resulting N04 source bytes and OOD question-set hash must exactly match the accepted 19a predecessor. Then the existing 19a validator must independently prove the three N03 files and its 25 Reason-only restorations. Its `reasonAmendmentQuestionIds` is deliberately separate from the accumulated semantic replacement list (`:7055-7058`, result projection `:7362-7368`); keep that distinction and the existing 450 mappings intact. The N04 content-correction list is likewise separate from both.

There is also a global historical consumer to account for: `verifyMigration` at `:7314-7331` uses the loader's `replacements` to remove current objects and restore `oldQuestion` objects before comparing with the historical rows. If same-ID N04 corrections are omitted from that historical reconstruction, the current corrected object remains and the historical comparison will use the wrong content. If they are added to the existing `replacements` result without separation, the report at `:7362-7365` will present them as semantic ID mappings and inflate the established 450 count. The eventual implementation therefore needs fixed, internal restoration records for same-ID corrections to reach the historical comparison while the exported semantic replacement list contains only true old-ID→new-ID mappings. An equivalent exact predecessor reconstruction is acceptable if it preserves both behaviors; do not count same-ID edits as new semantic mappings.

The downstream chain must continue to reconstruct and validate 19a→19→17→16→13→12→11 using the unchanged fixed descriptors and historical bytes. Current N04 validation should fail closed for an unknown version, missing/extra/duplicate per-item record, altered identity action, wrong old/current object, altered unrelated field, wrong source file or node, tampered proof/source, symlinked path, stale predecessor hash, and an unrelated catalog/source change. A same-ID correction negative case should prove that a changed same-ID object is accepted only when its exact before-object restores the predecessor bytes; an unlisted same-ID edit must fail. New-ID cases should prove the inverse ID membership and exact restoration. Keep these as temporary-fixture tests and preserve all existing historical fixtures and proof bytes.

## Boundary

The accepted package20 manifest currently covers 162 N04 items in nine source files. Its reserved IDs are proposals, not proof that each item must receive a new identity. This preflight therefore leaves the exact action map, proof field schema, implementation diff and any baseline-hash changes for the subsequent frozen identity review and independent migration design review. No general proof override, caller-selected mapping, waiver, fallback loader, widened pool, or alternate migration pipeline is supported by the current contracts.
