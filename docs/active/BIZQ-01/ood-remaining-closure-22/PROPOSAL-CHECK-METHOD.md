# Proposal mechanical check

Missing fact: each new unit proposal must still satisfy the actual canonical question contract, match one before/reserved identity in the closed manifest, retain taxonomy/difficulty/interaction/scoring/Details shape, score every option consistently after reversal, and bind every wrong diagnostic to its exact option. These are existing requirements, not semantic acceptance or a new global uniqueness/length/replacement rule.

Before building the narrow checker, root probed the real current `validateQuestion`/`scoreQuestion` functions on manifest B01i001 using Node22. The object validated; the correct option earned1/1 and the reversed-option result was exactly equal. `check-proposal-unit.mjs N06-Bxx.json` now applies those existing functions to one complete proposal array. It does not judge plausible alternatives, factual correctness, causal explanation, meaning-preserving identity, source claims, disclosure or transfer. Independent whole-object QA owns those conclusions.

`freeze-proposal-input.mjs N06-Bxx.json vN` preserves a submitted complete18-object unit with exclusive copy, verifies frozen/source bytes and refuses a different overwrite. Root tested `COPYFILE_EXCL` in a small actual Node22 filesystem probe: the second copy failed EEXIST and the original frozen bytes remained. The temporary probe directory was removed. This establishes the used filesystem primitive; it does not establish item semantics. Historical REVISE inputs/reports remain evidence, and a correction uses a new explicit revision.

## Advisory warnings from the existing console

Missing fact: which current console warning flags apply to the exact frozen proposal revisions, before the reviewer resolves significant warnings. Root first made a smallest real probe with one actual frozen B01 object in a temporary nine-track directory inventory. The existing `createContentReviewConsole` read exactly that object, reported `unreviewed`, and emitted `correct_option_sole_longest`; no outcome was written. The temporary directory was removed.

`inspect-frozen-proposal-warnings.mjs` versions the bounded wrapper around that same existing console. It copies only explicit frozen units into a temporary inventory, asserts exact unit/taxonomy/count correspondence, calls the console read API, emits input hashes and advisory flags, and removes its temporary directory in finally. It does not extract/reimplement riskFlags, add a heuristic or record approval. Actual first execution binds B01–B05 v1, B06 v2 and B07 v1 in `ROOT-FROZEN-WARNINGS-v1.json`:126 objects,76 items with advisory flags. That is neither76 defects nor a source-bank denominator. Independent semantic review resolves the flags against actual option specificity and decision cues. Additional units or revisions require an explicitly new receipt; old evidence remains immutable.
