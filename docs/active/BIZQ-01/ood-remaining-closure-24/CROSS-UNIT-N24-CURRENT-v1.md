## Blocking findings

1. **N08-B09 i001–i018: the primary decision changed.** The manifest before items decide where a retry/idempotency invariant belongs: inside an enforcing object owner versus coordinator sequencing, representation leakage, inheritance, or speculative indirection. The v4 proposals instead ask which request/operation ID scope governs retry and a later operation. The key changes from “put the invariant in the enforcing owner” to “replay/look up by this operation ID; use a distinct ID for new work.” The old `questionId` and `owner_preserves_contract` are retained, although the accepted answer meaning changed. The shift was already present in v3; v4 did not cause it. Use each reserved question ID with a new accepted-option ID, or restore the owner-boundary decision. The invoice item’s retry/idempotency facet remains valid and is not evidence that its primary decision stayed the same.

2. **N09-B07 i019–i036: 68 of 72 feedback messages copy a full constraints sentence into a stock frame.** For example, i019’s `assumed_cache` message says “Here, a production profile shows repeated tax-service calls …; the tax service accepts a batch … This option does not target that measured work,” although the distractor is indefinite caching and the decisive defect is tax-rule freshness. In i020, the `wrong_cost_center` message reuses a cache explanation for “Increase cache lifetime,” leaving the target’s actual wrong component unexplained. This conflicts with the existing authored per-option causal-feedback requirement in guidelines §7/Q05 and the ban on generic wrong-answer templates. Repair those message leaves against their actual target option. The other four messages that do not contain a copied full constraint are not included in this finding.

3. **N09-B03-i007 and accepted N02-B03-i027: near-identical case and action.** Both use the regional produce listing, invalid price/stock, and a `Listing.publish` operation that validates before visibility. N02 already says every entry point must enforce the same rule; N09 adds that a second caller skips the stock check, then asks for the same owner-validation decision. This does not establish a separate feature-envy/misplaced-behavior task. Retarget i007 to a distinct visible behavior-placement case, or record a concrete deliberate reinforcement purpose that changes the learner task. This is a single pair finding under the existing §5B warning/disposition process, not a global uniqueness gate.
