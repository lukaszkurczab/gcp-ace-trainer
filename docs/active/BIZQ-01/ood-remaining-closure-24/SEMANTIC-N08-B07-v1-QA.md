## Blocking finding — accepted answer is always first and mostly longest

BIZQ-01 §4.2 requires checking learner-visible answer disclosure; §4.3 calls for eliminating a systematic longest-correct signal. In these 18 items, the correct answer is options index 0 every time, and 17/18 correct choices are strictly longer than every distractor. The option set content reinforces the same cue: the keyed option states a complete ownership/cleanup contract, while distractors often plainly leak a resource, conflate a caller wait with operation cancellation, transfer ownership to a global registry, or violate the explicit pre/post-commit condition. Examples: i001’s 140-character key is longest; i003’s 134-character key is longest; i013’s 148-character key is longest. i004 is not longest (106 versus a 121-character distractor), but it is still first. This finding rests on the direct answer-position disclosure and repeated content structure, not a numeric threshold or equal-length rule.

The current application path does not shuffle this list: canonicalQuestionViewModel maps interaction.options in order, CertificationPracticeSessionScreen passes that order through to responseControl, and PracticeResponseControls renders control.options.map in order. Therefore all18 correct answers would be presented first in the current renderer. Resolve this using the existing content/presentation owner before activation; this review does not prescribe a new product randomization policy. Rework the choices to preserve meaningful case decisions, not to hit a length target.
