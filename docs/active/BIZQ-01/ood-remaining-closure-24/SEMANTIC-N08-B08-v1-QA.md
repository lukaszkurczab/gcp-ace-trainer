## Blocking findings

### F1 — Correct answer is exposed by order and repeated answer form

BIZQ-01 §4.2 requires checking learner-visible answer disclosure; §4.3 requires removing systematic answer-form cues. For all18 items the accepted choice is option index0 and strictly longest. The actual current app path preserves this order: canonicalQuestionViewModel maps the canonical option array directly, CertificationPracticeSessionScreen passes it through, and PracticeResponseControls renders control.options in order. Thus the answer is visibly first in the current learner UI for every item. The length signal compounds this position cue: the keyed option usually states a complete multi-clause outcome while distractors contradict explicit commit, visibility, or retry facts. For instance i006 is 147 characters against an 108-character longest distractor; i010 is 146 against 82; i015 is 132 against 82. This is a concrete content disclosure issue, not a threshold or an equal-length requirement. Resolve the direct position cue using the existing content/presentation owner and maintain credible scenario-specific alternatives; do not target a word count or prescribe a new randomization policy.

### F2 — i010 key adds an access-check mechanism not stated in the case

The i010 stem states that revocation committed at the authority, a door update service failed, and the operation must not claim propagation to that door until confirmation. The key correctly says keep the authority revocation and report propagation as pending, but adds “access checks use the authority result required by the scenario.” The stem never says the door can consult the authority synchronously or that checks bypass its stale local copy. That extra mechanism is neither needed to answer the asked outcome nor grounded in a visible premise. Remove that clause or add the exact existing contract fact if it is required; keep the answer focused on committed authority state versus pending door propagation. This is a §4.1–4.2 visible-premise/one-best-answer correction, not an assumed security architecture.
