# Independent design review — Q14 warning path

**Verdict: PASS for the bounded warning-only design.** The proposal addresses the existing §5B/Q14 evidence gap through the canonical review console and its already registered test suite. It does not alter item validity, scoring, outcome recording, source identity, admission, or the active N05 preflight.

The design fits the actual contract. §5B says text heuristics create warnings for human resolution; they must not accept or reject items. Q14 requests one synthetic unusually long correct single-choice option that remains valid and correctly scored. The current console’s `riskFlags` are derived from source objects, and `riskOnly` only filters the review list; an outcome is written only by the separate explicit `recordOutcome` call. The proposed `correct_option_sole_longest` therefore extends the right existing path without creating a new status or review pipeline.

The guarded predicate is a reasonable minimal choice: apply only to a well-formed `choice_single` with a resolvable answer option ID, at least two options, and usable option text; warn only when the correct option is strictly longer than every distractor. A tie or a long incorrect option should not match. Reusing OOD17’s existing strict-comparison heuristic avoids inventing a numeric cutoff. The new synthetic test should validate the item through the real question contract, score each option in both original and reversed order, observe the flag through `riskOnly`, and confirm the item remains unreviewed with no outcomes file written. Malformed choice data should not make risk scanning throw or replace schema validation.

The proposed update to the existing constraint-warning test is necessary for a clean regression assertion: it should count items carrying the constraint signal, rather than assume that no other warning can place an item in `riskOnly`. The source-slice test remains a useful regression check for the corrected cohort and visible remaining warnings. Both tests are already listed in `test:canonical`; no command or approval-gate expansion is needed.

There is a real breadth tradeoff, but it does not overturn the design’s bounded scope. I evaluated the exact proposed predicate against the current console source records: 13,895 valid single-choice items; 11,593 have a sole longest keyed option. The existing console currently returns 1,535 risk-only items, all of which also match this predicate; applying it globally would add about 10,058 items to the advisory list. This is a useful caution about review-list volume and signal precision. It is not a new acceptance threshold or a reason to label those questions defective: the flag is informational, the UI defaults to the full list, and no outcome or score is changed. The implementation should preserve that warning-only behavior and avoid wording or tests that imply a sole-longest option is automatically wrong.

Scores for this proposal: objective/architecture fit **0.93**, simplicity **0.92**, risk **0.82**, maintainability **0.85**; minimum **0.82**. Risk and maintainability reflect the broad advisory volume, offset by the absence of automatic decisions or writes and by keeping the implementation inside the current console/test path.

This review assesses the approach only. It does not certify the synthetic fixture or any authored questions, and it does not accept N05 source work, native behavior, or full BIZQ-01 closure.
