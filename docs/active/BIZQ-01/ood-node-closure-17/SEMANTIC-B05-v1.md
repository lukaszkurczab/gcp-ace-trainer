## Cross-item and explanation defects

- **Repeated primary decisions:** i020/i035 both ask that current readers retain a captured configuration while new readers see a complete published replacement; i023/i028 both ask that a reproducible result retain the exact input/version provenance; i026/i034 both keep a corrected value unpublished until a separate approval/confirmation. These are concrete same-decision pairs, not merely shared principles. i032 also needs to be differentiated from i035 by emphasizing whole-rule-set validation/publication rather than repeating “in-flight reader keeps old snapshot.” A coherent correction can retain the valuable variants, but should change the decision/mechanism or decisive facts/options within these pairs so each item exercises a different transfer.
- **One copied distractor family for all 19:** Every item repeats the same four answer models—mutate the published object, shallow-copy while sharing nested values, expose a read-only view with another writer, or assign a new business identity. Some fit particular scenarios, such as the explicit nested-note case in i021; others are not made plausible by the stated facts. For example, the shallow-copy alternative depends on mutable nested state that is not stated in every prompt, and i024/i025/i029’s wrong-option feedback does not diagnose the distinctive atomic-plan, posting-receipt, or accepted-comment/retry-state boundary. The fixed stable IDs and 190 scorer cases establish scoring mechanics, not that these alternatives are persuasive or item-specific.
- **Reason/Application duplication in all 19:** `feedback.details.scenarioApplication` equals `feedback.reason` exactly for every item. The mechanism field and transfer rule also repeat verbatim across the cohort. The prompt/reason pairs often contain useful scenario facts, but the Details do not then apply the mechanism in a second, concrete step; they repeat the conclusion and attach generic correction/boundary text. This conflicts with the existing §4.4 intent for a coherent mechanism → application → nearest-error correction → boundary narrative. Keep shared unit-level teaching language where useful, but make each application and nearest-error explanation do item-specific work.
- **Answer-length heuristic:** No length-only rejection. The recorded advisory has only five sole-longest keys out of 19, and the spec sets no numeric threshold. The blocking concern is the repeated answer/distractor semantics and generic diagnostics, not a word-count rule.
