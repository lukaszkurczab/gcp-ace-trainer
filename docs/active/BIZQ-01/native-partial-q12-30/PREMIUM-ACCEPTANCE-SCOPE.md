# Premium admission evidence scope

**Finding:** an existing repository-owned iOS smoke runner can exercise the ordinary Design/OOD Premium admission path with an authenticated Firebase Auth emulator identity and a synthetic `active` entitlement response. This exercises the app's normal authenticated gate; it is not evidence of a real RevenueCat or store entitlement. The BIZQ-01 spec requires a “real, properly configured test profile,” while the already accepted profile-feasibility note interprets that as a profile satisfying the app's authenticated Premium-admission contract and explicitly says provider-specific proof is not a separate criterion. On that documented interpretation, the emulator-backed runner is suitable for app-gate/native-flow evidence, provided reports call it emulator-backed and synthetic.

The concrete path is `patternly/scripts/runDesignInterviewAud02cIos.mjs`. Its `TRACKS` includes `object-oriented-design-interview`; it starts the local backend with the entitlement fixture `expired` for the free checks, stops that owned process, starts it again with `active`, then authenticates and runs the Design Premium, timeout and result flows for each Design track. It uses the ordinary app account path, not the Settings switch. `aud02dAuthEvidence.mjs` signs in an E2E user against Firebase Auth Emulator, exchanges the token through the local backend, and signs in with the generation-pinned custom token. The backend `GET /v1/entitlements` route verifies the request and attaches the authenticated `request.userId` as `accountId` before returning the configured reader result.

The “active” result is deliberately synthetic. `dev-smoke.ts` injects `localSmokeRevenueCatEntitlementReader`; `localSmoke.ts` defaults to expired and only returns active when the smoke runner explicitly supplies `PATTERNLY_LOCAL_SMOKE_ENTITLEMENT_STATE=active`. The launcher says that this is a local entitlement fixture and not provider attestation. The API response's `source: "revenuecat"` field is the route's stable response shape; it does not convert the synthetic reader into real provider evidence. The 5/5 `localSmoke.test.ts` result previously recorded with the Premium sandbox preflight confirms the emulated route contract only.

This path does not make the Settings Premium-testing flag an admission override, weaken `authorizePremiumSessionStart`, alter service configuration, or require a real purchase. It supports testing the application's existing auth-bound admission behavior with a test identity and deterministic local entitlement input. It cannot substantiate a real subscription, RevenueCat provider read, App Store transaction, remote sandbox configuration, or actual entitled tester outside the emulator. Neither the spec nor the accepted profile-feasibility interpretation adds those provider facts as independent acceptance conditions.

There is an operational constraint in the current workspace. The Design runner first asserts that `127.0.0.1:8080` is free; if it is occupied, it exits before starting or stopping a process. It then owns the smoke API lifecycle, switching its process-local fixture from expired to active. Root reports that the shared API currently occupies that port with the expired fixture. Therefore the runner is a source-supported route, but it is not safe to run against the current shared service state. The smallest next step is to wait for the current service owner to release the port, then use the existing runner with the already configured local smoke app/E2E credentials. The runner signs in; it does not provision a Firebase Auth emulator identity. If the emulator account is absent, the existing registration UI can provision a local test identity, but no account was created or checked here. No environment values or credentials were inspected.
