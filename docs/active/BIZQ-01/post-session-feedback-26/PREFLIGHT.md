# Post-session authored-feedback preflight

## Finding

There is a concrete completed-review gap for canonical choice questions. Docs/17 says that practice preserves the authored `feedback.messages` relevant to the submitted stable option IDs, and that post-session review uses the same authored feedback contract. The live practice paths use the existing `projectCanonicalChoiceFeedbackMessages` helper, but the completed-review paths either never copy its output into their review models or drop it before rendering. The reusable `PracticeFeedbackBlock` already renders a supplied `messages` array, so this is a read-projection and consumer-wiring gap rather than a need for new content semantics, scoring, or presentation infrastructure.

The omission is confirmed for Certification Practice and Certification Exam: both review item models omit messages, and the shared `ExamReviewScreen` passes only reason/details/result/sources to `PracticeFeedbackBlock`. A read-only in-memory fixture probe showed that both an answered incorrect practice row and an answered incorrect exam row lack a `messages` property despite having a selected wrong option; an unanswered exam row also lacks one. The unanswered behavior is correct to preserve: there is no submitted response from which to select a `wrong_option` or `omitted_option` message. The repair should project messages only for an actual, validated attempt response and leave them absent when there is no attempt.

Coding Algorithms completed practice and Coding Mock Interview completed review have the same omission. `completedFeedbackItems` calls `composeCanonicalFeedback(question, response)`, which already computes canonical choice messages, but its returned item type/object contains only controls, reason, details and sources. Both `AlgorithmsPracticeReviewScreen` and `AlgorithmsInterviewSimulationReviewScreen` then pass only those existing fields into `PracticeFeedbackBlock`. For unanswered Coding Mock rows, the current builder substitutes the canonical answer to form display controls; a feedback fix must not turn that synthetic display response into a learner submission or expose distractor messages. Include messages only when a stored attempt exists. The current projector’s stable-ID helper already selects only authored messages for selected incorrect options and omitted required-correct options, in authored order.

Design Interview practice already uses the shared helper for its durable, materialized in-session response. It currently completes into the generic Result screen without an answer-review action. Design Interview Simulation review is a separate open-ended stage/rubric review: it renders saved text responses and rubric criteria rather than canonical choice questions. Neither is an existing completed canonical-choice review consumer to wire in this bounded correction. Adding a new Design practice review route or turning the Design Simulation rubric into option feedback would expand product behavior and is not part of this preflight.

## Smallest coherent correction

For completed Certification Practice and Exam, add an optional authored-message field to the existing review item projections, populate it with the current canonical helper from the exact stored attempt response, and pass it through `ExamReviewScreen` to the existing `PracticeFeedbackBlock`. Exam items without an attempt should keep messages absent; do not synthesize a response from the answer key. For Coding completed practice and Mock Interview, copy the already computed `composeCanonicalFeedback(...).messages` into the completed feedback item only when its occurrence has a stored attempt, then pass it through both existing Coding review screens. Keep the abandoned Coding summary, active-session feedback timing, answer controls, scores, content, option-order policy, and non-choice diagnostics unchanged.

Extend the existing real projection tests to cover an incorrect selected choice, a multiple-choice omitted-correct choice, a correct answer with no applicable messages, an unanswered exam/Coding row, and deferred session-end feedback remaining hidden before completed review. Retain the existing helper tests for unrelated distractors, response order and non-choice behavior. No new schema, global ordering rule, storage write, or native device run is needed to establish this fix.

## Evidence and limits

I ran the existing canonical feedback, Certification Practice/Exam projection, Coding completed-practice/Mock result, and Design durable-choice-feedback tests with Node 22: 28/28 passed. The Certification feedback timing/negative tests also passed 4/4. A separate in-memory projection probe reproduced missing messages in incorrect Certification Practice and Exam review rows and confirmed the unanswered Exam row had none. These checks establish that existing behavior/tests pass while the review projection fields are absent; they do not constitute implementation acceptance.

The native25 screenshot independently shows the same issue for one completed GCP Free Certification Practice item: its immediate practice view displayed the authored billing-account distractor message, while completed review displayed generic Reason/Details without that message. This report does not claim that screenshot proves all families; the other families are traced from current source and their existing integration tests. No device or persistent store was touched for this preflight.
