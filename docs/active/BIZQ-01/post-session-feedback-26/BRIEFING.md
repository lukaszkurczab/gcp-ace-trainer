# BIZQ-01 — post-session authored diagnostics 26

## Cel
Domknąć istniejący kontrakt authored feedback w obecnych canonical-choice konsumentach completed review: Certification Practice/Exam i Coding Practice/Interview Simulation. Użytkownik ma otrzymać te same diagnostyczne komunikaty dla wybranych błędnych i pominiętych poprawnych odpowiedzi, które już wyznacza kanoniczna prezentacja. BIZQ-01 pozostaje głównym obszarem `partial`; ten pakiet usuwa wspólną lukę feedback, nie zamyka całego obszaru ani gotowości wydaniowej.

## Ustalenia
Źródło wymagania: [kanoniczny runtime §8](../../../../../docs/17-training-runtime-and-interaction-spec.md): „Post-session review uses the same authored feedback contract as practice.” Nie powstaje nowe wymaganie produktowe ani bramka. Native25 na własnej completed Free GCP sesji `google-cloud-associate-cloud-engineer:certification-focus-practice:2` odtworzył brak authored komunikatu dla source D / native:d mimo obecnego Reason/Details. [Dowody native25](../native-common-runtime-25/ROOT-NATIVE-OBSERVATIONS.json). Current-source preflight wskazuje wspólną utratę pola `messages` w projekcjach Certification, wyniku Coding oraz trzech ekranach review. Coding już oblicza `composeCanonicalFeedback`, ale porzuca `messages`. Certification powinien użyć istniejącego `projectCanonicalChoiceFeedbackMessages`.

Design ordinary practice nie ma completed-answer review route, a Design simulation prezentuje text-stage/rubric review, więc nie jest konsumentem tego samego choice projection. Nie rozszerzać zakresu o nowy ekran. Completed-review source order nie ma osobnej jawnej bramki; nie zmieniać order policy. Scorer, źródła, feedback timing i verified-completion guards pozostają istniejącymi kontraktami.
