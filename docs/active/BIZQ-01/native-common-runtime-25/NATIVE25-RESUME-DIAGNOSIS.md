# Native 25 cold-resume diagnosis

**Finding: confirmed consumer-guard defect.** The ordinary canonical session producer and its resume validator agree on a configuration snapshot that has no `navigation` field. Both ordinary resume-route builders reject that exact snapshot because they require `navigation === "linear"`. The resulting unavailable recommendation explains the disabled Home action observed after the durable answer and cold restart.

The reproduction used the current production producer, not a hand-built fixture. After `contentPackageRuntimeOwner.verifyBundledPackages()`, it loaded the canonical catalog, prepared ordinary GCP Focus Practice and Design Interview Learn Framework sessions at length 10, called `validateResume`, and passed each produced session to its matching resume-route builder. For both sessions, `validateResume` passed and route construction failed with “requires its canonical immutable interaction configuration.” The GCP result matches the native evidence: the recorded Home hierarchy shows “Session in progress” and “Focus Practice,” but `patternly:home:primary-action` is disabled and the expected resume selector is absent.

The failure path is narrow. `buildHomeTabModel` catches the route-builder exception and returns an unavailable, disabled recommendation. `HomeTab` therefore renders its general primary-action selector instead of the resume-card selector. The failure occurs before `HomeScreen` invokes the normal resume action; it does not indicate a missing session, invalid answer, lost durable ACK, or a need to bypass the existing identity checks.

The smallest coherent correction is to make both ordinary route guards agree with the existing canonical snapshot: accept an absent `navigation` field, while rejecting any explicitly present value. Keep the producer snapshot and fingerprint unchanged. Preserve all current status, family, mode, package, length, feedback, submission, answer-change, timer, reinsert, session-identity, and lifecycle/fingerprint checks. Do not add a `navigation` property to the producer snapshot: `CanonicalTrainingRuntime.validateResume` compares the exact snapshot and its fingerprint, and currently accepts only the field set it produces. Update synthetic fixtures that currently inject `navigation: "linear"`, and add a regression that uses `CanonicalTrainingRuntime.prepare` through route construction and the Home recommendation. Retain a negative case showing explicit navigation data is rejected.

The source bindings and reproduction are recorded in [NATIVE25-RESUME-DIAGNOSIS.json](NATIVE25-RESUME-DIAGNOSIS.json). After the failure reproduction, the implementation owner applied the proposed property-presence guard to both route consumers and updated the regression test in the shared working tree. Those edits postdate the reproduced failure; this diagnosis does not certify them or claim their tests passed. Native evidence is the observed cold-restart result; this diagnosis does not read private device storage or claim a completed native rerun. The controlled source reproduction itself did not change device, storage, source, or runtime state.
