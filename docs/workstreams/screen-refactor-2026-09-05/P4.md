## Confirmed facts and assumptions

- `SettingsTab` duplicated appearance labels in a hand-written EN/PL map, displayed a fixed `Version 0.1.0 · Build 1`, and described practice as `20 items · After each answer` even though `HomeScreen` opens `PRACTICE_SETUP` with only a track id and no persisted global practice preference.
- `expo-constants` was not a direct dependency or existing source import. The existing package metadata is available locally, so the Settings footer uses the package version and omits the native build number when no owned runtime source is available. No dependency or lockfile change was needed.
- `AppearanceSettingsScreen` was the only runtime consumer of `PreferenceSelectionScreen`; `rg` confirmed the remaining matches are the scope brief and the removal assertion. The typed selection UI now lives in the appearance screen.
- `setAppearance` is an asynchronous provider operation that can reject. Appearance choices therefore expose a synchronous ref lock, mount guard, disabled rows, a busy indicator, and a localized warning that leaves the current choice intact after failure.
- `SettingsInformationScreen` previously stored a translated topic object. It now stores section/topic positions and derives the topic from the current translated sections, so changing locale while a sheet is open cannot display stale-language content. Information rows now expose a trailing chevron.
- `SettingsGroup`'s divider mode is used by the Settings surfaces and the storage/developer groups. Its opt-in wrapper now owns the border, radius, and surface while preserving the existing non-divider spacing behavior.
- The account data contract contains an explicit adoption preview/confirm and restoration path. The YourData copy now states that confirmed account-owned records restore only through that explicit flow while preserving the existing backup and out-of-control-copy limitations. Legal-information promises and public-link validation were not rewritten.
- The shared SettingsBottomSheet changes from P3 provide the visible Close button inside `accessibilityViewIsModal` and automatic keyboard insets; P4 continues to use that shared behavior for information sheets.

## Changes

- Replaced the Settings appearance map with the `appearance` namespace, changed the practice detail to an honest session-setup description, and moved valued row metadata into the detail copy at `fontScale >= 1.3` so large text does not squeeze the right column.

## Risks and limits

The package version is real repository metadata, while the native build number is intentionally omitted until an owned runtime source is available. Native large-text rendering, modal accessibility enumeration, and locale switching on an active device still need the controller's P5 smoke pass; the focused checks are source/model contracts rather than renderer tests. Appearance persistence remains owned by `AppPreferencesProvider`, and a failed save is retried by selecting the desired option again.
