# P7 — Settings account and language preferences

Status: implementation stable in the shared checkout; independent QA and native verification remain parent owned. No commit created.

Implementation agent: `gpt-5.6-luna`, reasoning `max`.

## Decision and fit

The implementation scores 0.94 for consistency, 0.89 for simplicity, 0.84 for risk, and 0.90 for maintainability (minimum 0.84). It keeps AccountEntry as the single state-driven account route, calls the existing guarded account provider command for sign-out, and exposes the already persisted language preference without adding backend capabilities. The main risk is asynchronous sign-out state changing the navigator while Settings is mounted; the shared command lock, provider lifecycle states, and existing recovery screen keep that transition explicit.

Independent pre-implementation validation used the required three-section briefing with `gpt-5.6-luna`, reasoning `max`. The recorded briefing scores are 0.86 / 0.84 / 0.82 / 0.87, minimum 0.82, in `followup-progress-account.md`.

## Changed contracts

- `getSettingsAccountPresentation` maps every `AccountState` into a narrow Settings view. Guests expose a sign-in/create-account entry with local-only copy and no sign-out. Authenticated users expose email, sync attention when needed, and provider-backed sign-out. Busy lifecycle states disable invalid account actions.
- Home passes the derived account view and `account.signOut()` to Settings. Guest account navigation explicitly opens the sign-in mode; authenticated navigation still enters the existing AccountManagementScreen, AccountAdoptionScreen, or AccountRecoveryScreen selected by AccountEntry.
- `useAccountCommand` is shared by AccountEntry and Settings. It supplies the synchronous single-flight lock, mounted-result guard, busy action, and explicit remote failure fallback.
- Settings now exposes the existing `system` / `en` / `pl` preference through `LanguageSettingsScreen`. It persists through `AppPreferencesProvider.setLanguage`, blocks concurrent writes, and presents a localized save error. The default remains English.
- Account management now uses management-specific copy, removes the repeated Account heading, and shows the signed-in email when available. Recovery-code and deletion behavior remain unchanged.
